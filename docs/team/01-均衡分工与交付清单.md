# 鲜链智控：面向三个 Agent 的均衡分工

> 历史 v3。2026-10-10 用户要求十月底完成且 A 不能每日投入 3—5 小时，最新实施规则见 `v4/00-月底交付总方案.md` 和对应接入/角色指令。此文保留模块设计参考，不按旧实施节奏一次展开全部功能。

版本 v3。依据：用户提供的完整赛道二通知、已确定的项目范围，以及用户“不要按队长身份、几乎全程 Agent 开发”的调整。

本版人员分工替代之前 v1/v2，不替换赛事要求与项目科学边界。本方案的均衡是对工作链和依赖的估计，不声称可以准确预测各 Agent 耗时；两次短迭代后按真实阻塞调整单个任务包。

## 1. 上一版为什么失衡

A 同时控制公共接口、数据库、全部业务后端、设备通信、通知、部署、合并、设计文档和测试汇总。B/C 的开发经常需要等待 A。即使 AI 写代码，这些跨模块集成与排错依然会集中到 A。

v3 按完整业务模块分：每位 Agent 都交付自己模块的页面、接口、数据库结构、测试与说明。这样能在一个工作区内完成一个功能，再通过少量稳定接口与其他模块连接。集成轮值，功能缺陷仍由原模块 Agent 负责；轮值人不代修所有问题。

## 2. 固定项目与技术边界

- 题目：鲜链智控——面向农产品冷链仓储的品质风险评估、异常预警与智能调控平台。
- 两个冷库、三个相同明确品种的苹果批次；每库两个温度测点、湿度、门磁、主/备用制冷机和电表，共十四个逻辑设备。
- 一个仓库、一个 React/TypeScript/Vite 前端、一个 FastAPI 后端、一个 PostgreSQL 数据库，Mosquitto 通信；Python 算法和模拟器。
- 初版两种用户权限，人工确认调控；高级自动优化、复杂工单、节能实验可后加。
- 数据质量、真实环境异常、食品品质结论区分：不能把真实升温清洗掉，不能把环境暴露说成变质概率，恢复后历史暴露不清零。
- 每人本地有同版本环境和独立开发数据库。最终部署一套完整程序，不把三个模块部署为三套微服务。
- 学校通知原文参考：https://xxgc.sicau.edu.cn/info/1043/17644.htm 。后续群内要求需人工核对；无须按队长身份分配开发任务。

## 3. 三条完整工作线

| 人员 | 功能线 | 自己要交付的页面 | 主要材料成品 |
|---|---|---|---|
| A | 设备模拟、通信、注册、在线状态、控制回执 | 设备管理、设备详情/控制、模拟情境控制 | 基础运行/发布包、架构与 ER 汇编、成果视频 |
| B | 冷库批次、规则管理、告警处置、两种通知 | 登录外壳/导航、业务总览、冷库/批次、告警/追溯/通知配置 | 软件设计文档汇编、项目 PPT |
| C | 遥测存储、数据质量、历史导出、模型风险与实验 | 数据历史/质量、风险/算法实验可视化 | 算法报告、算法数据/复现材料、测试报告汇编 |

页面可使用页签合并，复用模板组件，不追求页面数量。A/C 自己完成对应页面，B 只提供通用布局与样式约定，不负责替他们写完或重做。

## 4. A 的具体任务

### A1 共同基础（短阶段）

从已选全栈模板跑通数据库、后端、前端、现有登录；建立基础 Compose、环境样例和版本锁定。只负责共用基础，不提前替 B/C 建所有表、写所有 API。完成标准是另外两台电脑按说明能启动，不是所有业务已做好。

A 提供公共认证与权限检查工具；B 复用它做业务页面与业务权限，C 复用它保护数据和算法接口。

B 同时给出业务对象/告警输入草案及前端布局，C 同时给出遥测/质量/风险输入输出草案。公共契约是三方各写自己部分并共同核对，不再由 A 独自设计全部。

### A2 设备管理与在线状态

负责设备表/迁移、注册 API、设备接入凭据、MQTT 主题权限、心跳和离线判断，以及相应网页。设备通过 B 提供的冷库 ID 关联，不直接修改 B 的表。离线/恢复事件交给 B 处理告警。

### A3 模拟器

模拟器由原先的 C 移到 A，让通信、执行器和控制逻辑在一个 Agent 内闭合。实现十四逻辑设备、固定种子、正常/短开门/长开门/制冷下降/测点故障/离线/命令失败等情境。动作改变后续模拟温度与功耗；场景标签只用于实验标注，不能泄漏给检测模型。

C 提出数据质量与实验所需情境，A 提供可批量运行和导出观测的稳定接口。C 自己生成实验数据与划分，A 不承担模型实验。

### A4 通信与控制

负责 MQTT 传输接收、认证与设备识别，将合法遥测交给 C 的处理入口；不实现 C 的历史数据库和清洗算法。负责完整控制 API、网页、命令编号、执行/失败/超时/过期、设备回执和实际状态。

控制日志由 A 保存，B 通过只读接口引用到故障时间线。设备控制不依赖 B 的告警页面才能测试。

### A5 本模块验证与交付

验证未知设备、离线/重连、指令失败/超时/过期/重复、实际数据反馈。编写设备/通信/模拟器说明和测试记录。维护运行包与启动说明，每个模块作者提供本模块依赖及配置，由 A 整理可运行交付物；模块缺陷返原作者。

架构图由 A 汇编，B/C 提供自己模块关系；ER 图从三人的模型/迁移汇总生成，不要求 A 替 B/C 设计表。

### A6 视频成品

A 负责主录屏计划、拼接/字幕/音量与导出，尽量用 Agent 处理。B 必须提供告警实收/仓储处置素材，C 必须提供算法效果图与说明；A 不重写他们的内容。成片来自真实运行，缺素材就记录待补，不虚构收件。

Agent 可根据已有权限与工具录屏、处理媒体；手机实际操作、账号登录或不可访问的外部环境仍可能需要同学配合。软件稳定前先定分镜，正式录制安排在版本冻结后，避免重复返工。

## 5. B 的具体任务

### B1 前端公共外壳与业务对象

确定复用模板的导航、通用表格/图表风格、状态文案、空数据与错误显示约定。提供一个示例页供 A/C 复用，之后不接管他们的页面。

负责冷库、批次、入出库、储存规则和规则版本的数据表、API 与页面；同一品种首版，避免跨品类储存冲突。提供只读的在库批次和规则快照接口，供 C 计算暴露。规则资料由 C 核查并提供出处，B 保存配置。

### B2 告警与处理

负责告警候选输入、去重、升级、确认、恢复、关闭及处理说明的后端与页面。接收 A 的设备离线/故障事件，接收 C 的数据异常/风险事件。不能只实现温度超限而忘记离线告警。

告警事件与受影响批次关联，引用 A 的控制日志和 C 的观测/风险证据；不在自己模块重新计算模型。确认告警不等于设备修复；处理记录要保存人员和时间。

### B3 两种外部通知

SMTP 邮件＋第三方 Android 推送是优先验证方案。B 独立完成后端发送、待发记录、重试、渠道状态与配置页面；第一轮即可用手动测试事件验证，不等 C 的模型。需要实际测试收件账号、设备和用户授权；第三方 APP 告警是否被认可应尽早询问组委会。

记录 queued/accepted/failed 等真实状态，服务返回成功不能冒充终端已读。两种邮箱不算两种渠道，站内弹窗不凑第二渠道。若通道资格/网络阻塞，及早替换为被认可且可实际使用的渠道，不拖到提交前。

### B4 本模块验证与设计文档

测试冷库/批次规则、业务权限、重复告警、告警恢复、两个渠道、发送失败/重试、事件追溯。编写需求与业务设计、界面说明和操作手册。

汇编软件设计文档：A 提供设备、通信、基础部署与架构/ER，C 提供数据/算法接入与测试报告，B 汇编排版，不代写。每人审核自己的章节。

### B5 PPT 成品

B 负责统一排版；三人各交四页内容、图、结论、证据与讲稿。B 不负责剪辑视频成品，解除上一版“全部前端＋PPT＋视频”的负担。

## 6. C 的具体任务

### C1 数据处理与存储

负责遥测原始数据、质量标记、有效数据与风险结果的数据模型/迁移、处理服务和接口。A 将消息交给 C 的统一入口后，由 C 做去重、校验、质量判定、保存和算法调用。

保留原始观测；对缺测/无效数据标记，不把真实温度超限平滑掉。在线算法不使用未来数据，历史窗口不足显示预热/数据不足。

### C2 历史、导出与数据页面

负责历史筛选、分页、CSV 导出和对应网页；负责共享的实时遥测查询接口，A/B 页面使用同一数据源。导出包含单位、采样时间与质量标记，记录数与条件一致。

C 提供实时曲线/质量图的可复用组件与使用样例，A 可以在设备详情嵌入，B 可以在业务总览引用，避免三个 Agent 写出不同的数据口径。

### C3 风险与异常检测

核查选定品种的参数来源，给 B 管理规则。实现固定阈值基线、Isolation Forest、当前风险和批次累计环境暴露；通过 B 的只读规则/批次输入计算，不能绕过业务直接改批次表。

结果写入自己数据模块，生成告警候选交给 B。候选含可追溯来源 ID、对象、时刻、分级和依据，不能偷偷生成已经通知成功的事件。环境恢复后当前风险可以降低，历史暴露保留；不宣称实际腐败概率或真实保质期。

### C4 实验数据与可视化

通过 A 的模拟器接口运行独立场景，C 负责实验配置、种子、训练/验证/测试划分和样本统计。按整段情境划分，避免相邻窗口泄漏；故障标签不进模型特征。

完成算法页面和实验图，比较基线与模型的检出、误报、漏报和检测延迟。模型结果差也保留，不能造提升率。节能对照是后续增强，不先承诺。

### C5 本模块报告与全队测试汇编

完成算法报告、算法源代码关联说明、数据/样本/生成规则/样本量/来源、复现实验说明，以及数据和算法模块测试。

C 汇编全队测试报告，但 A/B 必须提供结构一致的实际测试记录。优先由脚本或 Agent 整合已有证据，不让 C 替另外两人重新手测每个功能。C 不承担模拟器代码开发，不承担视频剪辑或软件设计文档总编。

## 7. 为什么这版更均衡

| 项目 | A | B | C |
|---|---|---|---|
| 主要调试难点 | 设备状态、通信和命令反馈 | 业务状态、两种通知及可追溯性 | 数据有效性、模型验证和结果解释 |
| 页面责任 | 设备、控制、情境 | 仓储、告警、业务总览与公共布局 | 历史、质量、算法和实验 |
| 后端责任 | 基础认证、设备/通信/控制 | 仓储/批次/告警/通知 | 数据存储/查询/导出/算法 |
| 主要材料 | 可运行包、架构/ER、视频 | 软件设计文档汇编、PPT | 算法/数据材料、测试报告汇编 |
| 不再背负的工作 | 全业务后端、全部通知、所有合并/报告 | 所有模块页面、视频成品 | 模拟器开发、独立补测全系统 |

无法保证三人耗时完全相同，但任务复杂度和集成依赖分散了。先完成两个小迭代，再看实际阻塞。需要转移任务时转移完整的小模块（含页面/API/测试），不要只转移“帮忙调一下”而无人负责收尾。

## 8. 少量公共接口，三人共同制定

业务模块保留在同一个 FastAPI 工程，下面是逻辑边界，不表示增加网络微服务。

| 接口 | 提供/调用 | 约定内容 |
|---|---|---|
| 合法设备观测交接 | A→C | 设备/冷库 ID、消息 ID、采样/接收时间、指标、单位 |
| 设备离线/恢复候选 | A→B | 来源事件 ID、设备、时间、原因、当前状态 |
| 数据/风险异常候选 | C→B | 来源事件 ID、相关观测、对象、严重度、原因、恢复候选 |
| 批次/规则快照 | B→C | 在库区间、品种、规则版本、上下限、适用条件 |
| 遥测与风险查询 | C→A/B | 统一时间范围、单位、质量、风险/数据不足状态 |
| 控制命令/记录 | A→B | 授权操作入口、command_id、执行状态、事件关联标识 |

公共要求：UTC 保存、北京时间展示；单位固定；ID 唯一；同一事件重复投递不能产生多份告警；各模块状态与错误含义明确。跨模块候选事件要么与数据事务一起入待处理记录后重试，要么采用等效的可追溯机制，不能因一次调用失败静默丢告警。使用现有 PostgreSQL 即可，不为此增加 Kafka 等设施。

集成适配层只做模块连接，不重写业务。根入口/公共事件契约由当次轮值者统一调整，其他模块通过依赖注入或注册接入，避免循环导入。具体代码结构在公共基础阶段确定，不能三人分别另造一套入口。

## 10. Agent 工作方式与人的必要配合

Agent 应承担：读规范、实现前后端、写迁移与模拟器、运行可访问环境的测试、排错、写模块说明、据真实结果做图、生成报告/PPT、根据已有录屏处理视频、整理交付包。

同学承担：账号/邮箱/手机授权、安装环境需要的本机交互、提供另一台电脑与手机上的实际运行结果、确认业务与赛事口径、检查交付物、理解并练习答辩。工具不可访问的设备操作由人补上，不保证所有电脑/手机都能被远程自动控制。

每个小任务给 Agent 五项信息：范围、所属目录、公共接口、验收步骤、交付位置。要求它输出实际检查及未完成项，不只给代码和“已完成”。

集成轮值：第一轮 A、第二轮 B、第三轮 C，之后循环。轮值 Agent 拉取各模块、合并、跑主链路、记录问题；问题返模块作者修。A 长期负责的只是基础运行配置和交付包，不是所有故障的兜底者。

## 11. PPT、视频和文档明确分摊

### PPT：B 统一排版，三人各供四页

| 页码 | 主题 | 内容责任人 |
|---|---|---|
| 1 | 项目与业务问题 | B |
| 2 | 场景和完整业务流程 | B |
| 3 | 系统架构 | A |
| 4 | 虚拟设备与通信 | A |
| 5 | 控制、回执与设备异常 | A |
| 6 | 仓储批次、告警和故障追溯 | B |
| 7 | 数据质量与原始证据 | C |
| 8 | 批次品质相关环境风险 | C |
| 9 | 异常检测与业务融合 | C |
| 10 | 独立实验、效果与局限 | C |
| 11 | 可运行交付与可靠性检查 | A |
| 12 | 完成度、团队贡献和边界 | B |

十二页是内容建议，实际页数/讲解时长按赛事要求。每人交图、来源、实际数字、3—5 个要点和短讲稿。B 统一视觉和表达，技术原作者最终签核。

### 视频：A 汇编，三人各交自己模块素材

- A：设备上线、模拟情境、控制/回执、运行说明；编排录制、剪辑和导出。
- B：批次、两通道真实收件、确认/处置/追溯；提供对应讲稿。
- C：清洗标记、风险/累计暴露、算法对比；提供解释和实验图。
- 三人：在固定发布版本走主流程，核对时间线和数值；另一台电脑播放成片。

能连续录制的主流程优先连续录制，再插入手机收件或算法解释片段。视频技术故障按模块返修，不默认由 A 全部解决。

### 文档：每人写模块，B/C 分别汇编

- 软件设计文档 B 汇编：B 写需求/业务/页面；A 写基础架构/设备通信/控制/部署并汇编架构与 ER；C 写数据/清洗/算法接入。
- 测试报告 C 汇编：A/B/C 写自己的测试，C 只按统一格式整理证据和覆盖表。
- 算法设计报告 C：含原理、步骤、参数、性能验证、调用链与边界。
- 数据材料 C：生成规则、样本、样本量、来源、随机种子、训练/验证/测试划分与复现。
- 可运行包 A：B/C 提供可构建模块与所需配置；源码、模型、报告、PPT 和视频同版。

## 12. 原通知逐项归属

| 通知项 | 主责 | 需要配合 |
|---|---|---|
| 设备注册、在线监测 | A | B 提供冷库关联 |
| 远程控制 | A | B 引用到事件，C 提供变化观测 |
| 故障记录与溯源 | B | A 控制/设备日志，C 风险/观测 |
| 实时采集 | A 传输，C 存储/查询 | A/B 使用 C 数据接口 |
| 数据清洗与算法联动 | C | A 传原始数据，B 消费风险事件 |
| 历史查询与导出 | C | B 提供批次时间区间 |
| 两种告警与记录 | B | A 设备事件，C 数据/风险事件 |
| 算法业务融合与前端效果 | C | B 告警/建议，A 控制执行 |
| 完整带注释源码 | 三人各自负责，A 打包 | 每人提供第三方来源 |
| 可运行应用程序 | A 汇编 | B/C 各自提供运行模块并交叉安装验证 |
| 软件设计文档（需求/架构/ER/测试） | B 汇编 | A 架构/ER；C 汇编测试；三人写章节 |
| 算法设计报告、关联源码、实验数据 | C | A 模拟器版本，B 规则与实际接入 |
| 展示 PPT | B 汇编 | 每人四页内容 |
| 成果视频 | A 汇编 | B/C 提供自己模块真实素材 |

两种告警是硬性要求，PPT/视频也是必交；算法虽是加分项，但本项目选择使用，就需要配套算法报告、代码与数据。不要把开发计划当作测试报告。

## 13. 首轮与后续验收

首个短阶段：A 跑通基础与最小模拟器；B 设计业务对象/告警候选和布局，用指定测试对象验证两个通知渠道；C 定义数据处理与查询/风险接口，准备规则资料与最小数据处理。基础可用后立即并行，不要求 A 先实现所有表和接口。

第一轮共同结果：一个设备上报→C 保存→网页查看；A 远程控制→模拟器回执→数据变化；B 用实际候选事件触发两渠道。先用固定阈值打通，模型随后接入。

第二轮：扩到两个冷库，补批次、故障追溯、质量标记、历史/导出、风险/模型，三位 Agent 各完成自己的页面。

第三轮：独立算法实验、真实失败路径测试、第二机安装、三份模块说明、PPT 与视频素材。

最后：冻结版本，A 运行包/视频，B 软件文档/PPT，C 算法/数据/测试汇编；每人检查另一人的主要材料，再全员主流程演示。

不预设确切完成天数或排名；以实际截止时间和验收结果安排。若某人的剩余任务明显较长，优先冻结扩展、让已空闲 Agent 接一个独立任务包，例如视频字幕、来源清单或一次安装复核；不能让两位 Agent 同时改同一核心模块。

## 14. 完成与交接标准

每个任务交付：所属模块代码、对应网页或接口、实际测试证据、关键注释、模块说明、公共接口变化、提交版本、已知问题和下一步。跨模块功能必须联调后才算完成。

测试结果需包含版本、输入、步骤、预期、实际、证据位置和失败/复测；报告汇编者不能替作者写“通过”。图表和视频不能使用假收件、假执行或没有测过的指标。

所有同学最终至少独立跑通一次完整演示，并能说明三个问题：数据从哪里来，异常如何触发动作，报告中的效果如何得到。代码主要由 Agent 完成，不免除对作品的理解与实际运行核验。
