# 共同仓库接入与已有成果保护

## 已确认的本机事实

A 的模板启动和网页登录已通过。本机源码已有 Git 历史，目前分支为 master，唯一远程为官方模板 upstream，尚未连接团队远程。GitHub CLI 未在本轮命令查找中发现，不要求因此安装额外工具。B/C 是否已经开发及其本机运行状态未知。

当前只指导用户创建一个私有、空的团队 GitHub 仓库；此文档不表示仓库已经创建、代码已经提交/上传或同学已被邀请。

## 给 B/C 的立即交代

若 Agent 已经开始工作，不要删代码、重建项目或直接用 A 的文件覆盖。先结束/保存手头能验收的小任务，并整理自己的角色、实际工程目录、基于哪份模板/启动包、Git 基础提交（如果有）、改动文件、实际测试、问题和下一步。私有环境文件、密码/授权码和数据库不作为群内交接材料。

共同仓库地址确定前，可以继续自己的独立小模块、接口草案和资料核查，但暂不扩大范围，也不随意修改公共入口、框架/锁文件、根登录或另一人的模块。确有必须改的公共点，先在交接中列出改动建议，交轮值集成者协调。已有公共改动也保留并注明，不擅自回退丢弃。

B 继续仓储/告警/通知线，C 继续数据/算法线；每人负责自己模块的页面/API/表/测试/说明，不只交前端或算法脚本。保持同一 FastAPI/React/PostgreSQL 工程，不重建三套服务。

## 用户当前操作：创建空仓库

1. 登录 GitHub；无账号则本人注册并完成验证，不分享密码、验证码或令牌。
2. 打开 https://github.com/new 。Owner 选自己的账号；名称建议 freshlink-zhikong（已占用则选另一个可用名称）。
3. Visibility 选 Private。
4. 不选模板，不自动生成代码；不添加 README、.gitignore 或 License，已有工程将提供这些文件并保留上游许可证。
5. 创建后只发仓库网页地址给 A 本机 Agent。暂不粘贴 GitHub 页面的一整段初始化命令，不手动上传文件，不连接官方 upstream。

这是建立空容器，尚未上传源码。接下来单独完成本机改动检查、秘密检查、提交身份设置、基础版本保存、经授权连接/上传，再邀请同学获取同一基础版本。

## 接回 B/C 已有代码的办法

保留旧目录作为只读参考，从团队仓库获取一个新的工作目录。各自 Agent 比较旧代码与共同基础，只迁移本角色的已检查改动；必要公共改动记录并协调。不要整目录覆盖共同基础，不删除旧成果以求一致。

双方有共同 Git 历史时可按实际提交审查再迁移；无历史时按文件差异逐项迁移。不得在未知基线时盲目合并或强制推送。每个小任务在任务分支检查后请求合并。每台电脑生成自己的私有配置和数据库；禁止把 A 的密码当团队共享密码。

参考：GitHub 官方仓库创建说明 https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository 。官方明确已有工程导入时不应预填初始化文件以免引入合并冲突。
