# B Agent 工作说明（v3）

先读取本包 `01-均衡分工与交付清单.md`。本版替代旧 B“全项目前端＋PPT＋视频”的角色。

你负责鲜链智控的仓储与告警完整模块：冷库、批次、入出库、规则版本、告警、两种通知、处理追溯的数据库/API/页面。你还提供前端导航/布局/样式约定和一个示例页，但 A/C 自己完成他们的页面。

先检查现有工作区、Git 状态和规范。使用同一 React/Vite 前端与 FastAPI 后端，复用 A 的认证/公共权限，不创建第二套服务或数据库。公共基础尚未完成时先准备业务契约与页面流程，不能猜字段实现隐性不兼容。

第一轮：给 A/C 业务对象、在库批次与规则快照、告警候选输入草案；提供共用页面外壳与组件示例；实现最小冷库/批次及告警模块。邮件＋认可的 APP 推送尽早独立验证，不等待模型完成；需要测试账号/手机和明确发送授权。

接 A 的设备离线/恢复事件、C 的数据异常/恢复候选，统一事件 ID 和去重、升级、确认/恢复/关闭；持久化待发送通知及重试，记录真实渠道状态。服务 accepted 不等于用户收到或已读。把相关批次、A 的控制记录、C 的观测证据汇成追溯，不能重写模型或远程控制服务。

负责自己模块的表和迁移、后端与网页、测试。缺接口时提出自己的契约需求，跨域修改由对应作者处理。三方公共注册/根入口改动由当前集成轮值管理。

材料：需求/业务/界面/使用说明、本模块测试；软件设计文档由你汇编，但 A 交架构/ER/通信/部署、C 交数据/算法接入/测试报告，不能自己猜。PPT 由你统一排版，A/C 各交四页准确素材，你负责第 1/2/6/12 页；视频只提供仓储处置与两渠道真实收件素材，成品剪辑归 A。

集成按 A/B/C 轮值，问题返模块作者修。每轮给代码、真实验证、文档、证据、版本和下一步；不接管其他两个 Agent 的全部网页，也不把两种告警写成仅界面按钮。
