# 三人凭据安全与公开前检查

本文件是日常预防与发布流程，不是安全审计通过证明。仓库可见性、认证、CI、业务验收分别记录，不能相互替代。

## 三个 Agent 的认证

- A/B/C 使用各自账号、各自运行环境的授权，不共享队长令牌，不把凭据写入源码、聊天、日志、截图或提交。
- 本机优先复用 GitHub CLI 浏览器登录或已有凭据管理；云端核对 GitHub 连接的仓库访问和实际写入工具。本机环境变量不会自动传到云端。
- 需要个人访问令牌时，由本人创建最小权限、明确期限的凭据。先核对账号及令牌类型是否支持该协作仓库；不能选择仓库时先排查，不以共享其他人的令牌绕过。
- 环境变量只是传递方式，不是保险箱；持久环境、终端历史、调试输出都可能暴露秘密。避免打印全部环境、认证头或 credential helper 输出。
- 验证认证先只读核对身份与仓库，再发布一次有实际用途的本人 STATUS，记录实际链接。不要刷测试评论。令牌失效后不要拿它反复试登录。

## 每次准备提交

先保护用户改动，明确文件清单，不执行无差别 `git add .`。检查暂存区后运行：

```powershell
python scripts/check-publication-safety.py --staged
python scripts/test-publication-safety.py
```

检查已提交版本可用：

```powershell
python scripts/check-publication-safety.py --revision HEAD
```

检查只读扫描完整暂存快照或指定提交的文本，报告文件/规则/行号，不打印匹配值。退出 0 表示这个有限文本检查未检出，1 表示发现问题，2 表示检查未完成。图片/二进制、Git 历史、评论及 Actions 归档不在此脚本检查范围，不能将其通过称为“允许公开”。

继承的根 `.env` 是模板演示值，禁止写真实配置；真实 `.env.freshlink`、`work/`、数据库、缓存和私钥不得提交。配置样例只留无秘密占位符。私有文件排除规则命中也需人工核对，不能改名绕过。

## 重新公开的门禁

1. 已知泄露凭据由本人确认失效或提供可靠失效依据；删除当前代码不等于撤销。
2. 核对最新远程分支与 PR，检查 Git 历史、Issue/PR、Actions 日志/产物和真实个人信息；记录范围、失败和未检查项。
3. 真实收件地址等非必要个人信息脱敏。若历史仍保留，取得该信息所属本人对历史公开的明确同意，或者协调必要清理；不由其他成员替其同意。
4. 仓库所有者了解公开代码、历史、评论、日志和产物的影响，明确批准后才改可见性。不得凭其他 Agent 的评论自行改变权限。
5. 标准 GitHub 托管 runner 的公有仓库免费规则与大型 runner、第三方服务费用分别核对。不自动开启付费、调高预算或扩用收费 runner。

## 凭据失效与历史处理

优先撤销或轮换已泄露秘密，然后评估是否需要改写历史。Git 历史重写会影响 SHA、分支、PR 和队友克隆；必须另行取得团队协调及所有者批准，不默认强推。恢复 Private 不能收回外部复制或 fork。

安全排查细节先私下交本人，不向公开 Issue 发布秘密或未授权的敏感定位信息。共享任务只写安全的协作结论、实际 SHA、测试范围、阻塞及下一步。

## 持续协作

继续沿 S0 #5、E1 #6、A #7、B #8、C #9、材料 #12 和对应 PR 接续；Agent 每次运行都读取最新评论与当前提交。GitHub 不会自行唤醒其他电脑的 Agent。私有仓库仍可读写协作；本机测试与远程 CI 分别记录，不把认证、公开或 CI 成功当作 E1/最终验收成功。
