# A67：同版真实浏览器录像素材

这是验证工具与视频素材交付，不改变 main0e 的业务、前端、迁移或配置。
默认不录制；既有 `scripts/windows/check-live-control-browser.ps1` 增加
`-RecordVideo` 后，仅给管理员的专属浏览器 context 录制视频并在关键画面
停留三秒。退出时关闭 context 刷出 WebM；原有断言和失败留证继续有效。
不安装浏览器/依赖、不接触用户桌面，不启动真实通知。

## 本轮失败与最小修复

首轮录像源 `815c4a2a70f00d401b6583c1d6395898d4751004` 在页面等待
“已确认→已恢复”时失败，后台报告验证器失败；原失败录像和页面诊断保留于
`work/control-browser-20261027115206-45944/`，不能作为通过的视频。

验证器原来的 MQTT 温度观察器把所有重发也追加到500条容量中；连续记录期间，
正常重发可耗尽容量，也可能让旧样本的重复到达覆盖“最后温度”的含义。
现在按实际 message_id 和原始正文识别重发，只将首次的有效样本加入温度序列。
500个唯一采样的上限仍保留；同ID不同正文仍失败，不提高上限绕过错误。
新增固定脱敏的 harness-failure.json，区分采样错误与 worker 错误。

纯标准库四项回归实际通过：501次同样本重放、旧采样重发不倒退温度、同ID正文
冲突拒绝、唯一采样容量仍拒绝。没有应用/数据库导入；Ruff与格式检查通过。
这是验证器修复，不是修改设备生产行为，也不直接核销以前全部浏览器偶发失败。
