## 保存与确认边界

`TelemetryReceiver` 复用现有 TLS、证书校验、显式最多14设备范围与手动 ACK。
接收器只能使用经验证的只读服务账号；每个设备账号只能发布自己的遥测主题。
不是凭 topic 自称设备身份：先有真实 Broker ACL，再由 A 注册表和 B 实际仓库查询
构造可信 envelope，保存时再检查当前设备绑定。B 暂时读取失败不得当永久无仓库。

合法包的 exact UTF-8 原文、可信 device/warehouse、服务接收时间、reception ID、
摘要先提交 A inbox，之后才发 QoS1 ACK。**此 ACK 仅表示 A 已收妥，不表示 C 已入库、
质量正常或告警已发送。** C 继续拥有业务原始观测、质量、历史、快照与风险 outbox。
网络重投可以有新的 reception ID，但设备原 message ID 留在原文供 C 判重。
队列内部重试则始终使用原 envelope／reception ID，不能重新取接收时间。

接收循环不调用 C。独立 `TelemetryDeliveryWorker` 每次从 PG 领取一条租约，
关闭 A 事务后调用必填的 C 存储端口，之后再次核对租约、尝试号和原文摘要。
只有 C 返回匹配来源 ID 的终态回执，A 才在同一事务中保存终态元数据、移除自己的
待处理原文副本；C 已持久化的原文不删除。invalid/conflict 不是业务成功；返回了
错误来源 ID、缺观测 ID 的 accepted、未知状态等异常回执时，A 原包保留为 blocked。

## 有界失败行为

| 条件 | 实际行为 |
|---|---|
| 接收库/审计库不可用、容量满 | 不 ACK，停止接收器；不能丢包后继续报成功 |
| 无效 JSON、伪造身份、retain、非 QoS1 | 有界拒绝审计提交后才确认；QoS0 本身无法 ACK |
| C 暂时失败/抛错 | 原文留 PG；1/2/4/8/16/30秒封顶退避 |
| 运行器重启/租约超时 | 从 PG 领取原 envelope；30秒租约，尝试预算不重置 |
| 第10次失败或第10次领取后崩溃 | exhausted；保留原文，不无限重试/自动清理 |
| C 已提交但 A 终态提交丢失 | 保留租约与原文；到期同 ID 再调用 C，以 C 幂等保证不重复观测 |
| 管理员重试 | 重新查询活跃超级用户，显式重置一次预算并留 actor/次数审计；不修改原包 |
| 普通用户/停用管理员/活动租约重置 | 拒绝；没有公开重试 HTTP 入口，不冒充已接 UI |

默认最多1000条、32MiB未解决原文，单包上限32768 bytes；leased/blocked/exhausted 都
占容量，不通过删除失败包释放空间。容量检查与插入由 PG 单例行锁串行保护，含并发测试。
A 终态回执和拒绝审计**各**最多1000条、保留7天，仅含摘要/大小/固定原因/标识等元数据。
不会按此策略删除待处理原文或 C 业务历史；这不是永久保存全部传输日志的承诺。

MQTT5 使用稳定且专属的 client_id、`clean_start=False`、86400秒会话、ReceiveMaximum14、
最大包大小约33KiB；需同时验证 Broker 的会话/磁盘/容量设置。会话过期或 Broker 丢磁盘
不能由 A 代码保证找回未收妥消息。接收库失败后需修复并重启接收器，不能静默降级。

C 适配器必须具有明确的有限数据库/网络超时并在持久提交后返回。A 租约不是杀死挂起
C 调用的超时机制；不会为强行取消调用而启动无限线程。当前运行器要求显式注入 B/C
端口，未提供 permissive 默认、自动导入候选 C 或应用启动时 `create_all`。
