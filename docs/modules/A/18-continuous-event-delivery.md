## 从一次调用到持续执行

A06 的一次 `deliver_to_local_alerts` 保留原语义；A10 提供显式开启的
`EventDeliveryWorker`，在真实心跳所生成的 A 持久事件上持续尝试。
不要让 A06 手工投递器和 A10 同时负责同一事件，否则无法以 A10 的账本完整审计。
仅有配置不能运行：必须先具备已审核的 A/B 共同版本和数据库结构。

- 显式设备 UUID 白名单，1—14 个、不能重复，不扫描所有用户的全部设备。
- 原事件 ID、设备、发生时仓库、原时间、reason 和恢复关联作为不可变正文指纹。
  A `occurred_at` 映射 B 的 `sampled_at`；B DTO 无 reason，原 reason 留在 A 可追溯。
- A 的认领／检查点事务用短 PG advisory lock 串行化，B 服务调用不持有 A 事务。
  多投递器不能共享同一有效租约。B 接收通过自己的独立事务提交。
- 离线事件未取得匹配 B 落库回执并在 A 确认，恢复事件只能留在原历史等待；
  不占新投递预算，避免恢复事件挤满队列后饿死原离线事件。
- 只有匹配原 source、内容摘要、有效目标 UUID 的 accepted_new／duplicate
  才能原子标记 A 历史和账本 delivered；两个目标 ID 相互矛盾时拒绝成功。
  B 返回的 receipt 不等于通知终端实收，不在此处生成或发送通知。
- `held_unbound` 历史不发送，后绑定不能把旧仓库或空仓库改写。

## 有界重试与人工处理

租约30秒，每事件每轮最多10次，等待1/2/4/8/16/30秒封顶，次数和到期时间在 PG。
B 已提交而 A 检查点事务失败时，A 原 pending 和租约保留；过期后同 ID/正文重投，
B 去重后才再次提交 A 检查点。重建投递器/连接池不重置预算。
最后一次认领后进程中断，租约到期也不会出现第11次自动调用。

坏回执／无效恢复关联／正文变动为 blocked，预算耗尽为 exhausted；
两者都会把原 A delivery_state 标 failed，但不会改写原事件正文，也不会自动删除。
最多1000条未解决账本，达到上限的新事件仍留原始历史，等待容量释放，不丢事件。
成功账本与人工重试审计各按7天/1000条保留；不清理原 A/B 业务历史或未解决失败。
失败占满容量时需管理员处理，不自动丢弃以恢复“绿灯”。

`retry_event(engine, source_event_id, actor_id=...)` 在数据库中重新校验活跃管理员，
仅重启 blocked/exhausted 且正文未变的同一事件，重置该轮预算并原子记录操作者/轮次。
重复 queued 请求不重复审计；已投递／有效租约不重置；无权限不能绕过。
当前是内部服务端口，尚没有新管理 HTTP/页面，不冒称已具备失败处理 UI。

## 启动与正式接线边界

进程入口：`python -m app.modules.iot.event_worker --config <本机配置路径>`。
可选 `--max-seconds` 控制有限测试时长；停止信号可唤醒等待。
配置仅为 `enabled: true`、`device_ids: [UUID...]`、`poll_seconds: 1`，不含凭据；
未知字段、非法数量、重复 ID、非有限时间都拒绝。PG 参数沿本应用配置取得，
连接5秒、单语句5秒、有界数据库失败退避；不打印载荷/凭据/原异常详情。

新增独立 metadata 两表 `iot_event_delivery_checkpoint` 和
`iot_event_delivery_retry_audit`，**无 import/启动时 create_all，无正式迁移文件**。
测试只在严格一次性数据库/每测试唯一 schema 创建，结束只删自己已知表，不 CASCADE。
正式部署时 A 在三方认可的唯一实际 migration head 上接一次有审核的迁移，
核对 A/B 版本兼容、备份/升级/回退、旧事件待处理量，再接 Compose/服务监督；
不能把本候选的测试 DDL 或两个独立 metadata 当生产 schema 已就绪。
