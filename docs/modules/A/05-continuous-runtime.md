# A1.4：连续设备运行、心跳发出和进程重启

2026-10-12。基于PR #15的58e4bdea0de989a6af8571f72a68cec6a414b602，分支feature/a-simulator-runtime。这是一库一测点一执行器的设备侧真实MQTT运行器，**不是已接入主程序的在线监测、告警或完整E1**。共同main/S0状态仍以#5实际记录为准。

## 从上一阶段进入了什么阶段

上一阶段通过受控文件桥验证单次命令/执行/ACK；本阶段产品入口 `python -m app.modules.iot.simulator_runtime --config ...` 直接保持两个MQTT客户端连接，周期采样/心跳、订阅命令、执行、发出原ACK，不需要Agent逐包搬运文件。收到网络包是实际后台回调；业务状态仅由一个运行线程写本地设备状态。

依赖只增加 `paho-mqtt==2.1.0`（官方PyPI及锁定哈希）；uv.lock其余版本未升级。VERSION2回调、手动接收确认、网络循环/重连按 [Eclipse Paho官方文档](https://eclipse.dev/paho/files/paho.mqtt.python/html/client.html)使用；两个Properties构造器的局部mypy标注仅针对该版本缺失的库构造注解，未降低全局严格类型检查。

设备状态SQLite仅做兼容追加 `ack_transported` 与runtime_audit，保留上一版本命令/观测/身份；不是新的共享业务库或PostgreSQL迁移。增加原ACK待投递恢复、hash/长度/稳定原因的有界拒绝审计、明确restart_gap。公开配置示例与使用方式在 `simulator/README.md`。

## 当前行为和安全边界

| 项目 | 已实现 | 不能因此宣称 |
|---|---|---|
| 持续采样 | 默认30秒；每包原UUID/原字节持久待发，断连/重启可重传；按轮转批次最多16次发送，避免前32条堵住后续 | C已入库或网页已实时更新；本轮没有清待发 |
| 心跳发出 | 两个设备各自产生新UUID、UTC、非retained、QoS0短寿命心跳；停进程停止发，重启恢复 | last_seen已写入主程序、在线/离线/恢复事件已持久或已交B |
| 命令执行 | 本机自己的commands主题；只收QoS1，订阅retainAsPublished以识别正在运行时retained发布；状态/原ACK持久后才接收确认 | Broker PUBACK是设备执行，或库内队列等于跨进程持久化 |
| ACK重试 | 未发出的原ACK跨进程恢复；重复命令只重传原ACK，不再执行；新重传不被旧在途ACK错误清除 | 主程序已接受ACK或命令已变acknowledged；ACK Broker标记只有传输含义 |
| 连接/身份 | 测点和执行器分账号、默认TLS/主机名和证书检查；有界接收/发送，认证、订阅、发布被拒明确停 | 生产TLS/实际注册绑定凭据已验收；当前隔离账户/UUID是公开夹具 |
| 长停机 | >60秒显式保存缺口，冻结温度/电量、关闭模拟制冷并从新时刻继续；旧ACK/待发保留；倒退时钟拒绝 | 停机期间采样被补齐，或旧ACK能代表重启后的当前开关状态 |

没有匿名HTTP控制入口、任意shell执行、关闭证书校验或更换主技术栈；不读主程序私有.env、不向外部邮箱/手机发送。CLI长期运行在独立设备环境，Ctrl+C/SIGTERM停止；本轮测试每次运行后均清理进程/容器/网络，未留下无人监管的模拟进程。

容量或状态写失败会停止并保留证据，不吞掉后继续声称在线。待发1000、命令10000、审计1000、接收队列32、QoS在途16/排队32等为工程限制；没有吞吐/生产可靠性性能保证。接受命令仅依赖配置的可信Broker ACL，注册/绑定查询和主程序权限尚需接线。
