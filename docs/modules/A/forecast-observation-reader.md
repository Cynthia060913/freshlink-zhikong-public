# 预测观测只读接点

`iot/forecast_observations.py`是A的内部读取适配器。调用方提供已确认的设备、冷库、UTC决策时刻及窗口策略；没有公开HTTP路由、模型调用、规则评价或写入。后续服务仍须认证并校验调用范围，不能把这个内部函数当作鉴权接口。

## 读取与拒绝

设备绑定、设备类型及观测来自同一PostgreSQL `REPEATABLE READ`、`READ ONLY`事务。只允许已注册、已绑定到指定冷库的温度设备；未知设备、未绑定、执行器或冷库不匹配时不提供模型窗口。连接状态单列返回，不从温度数据推断设备在线或解除离线告警。

只读取观测ID、采样/首收时间、已清洗温度及质量，不返回原始载荷或当前风险结论。SQL先限制设备/冷库、`first_received_at_utc <= as_of`以及历史采样范围；质量不在SQL中筛成“全干净”，最近收到但缺采样时间的行也会进入守卫，避免SQL的NULL比较悄悄丢掉坏证据。未来到达和其它归属的数据不影响容量。

最多读`max_points+1`行；额外一行只用于确认超限，`rows_read`不是整个数据集计数。超限明确为`input_limit_exceeded`、无模型窗口，不裁掉旧坏数据来制造可预测结果。其余行交现有输入守卫；仅`ready`有模型点。数据库失败抛固定`forecast_observation_read_failed`，不伪造空查询成功，不向调用方带出SQL或配置细节。

该函数提供当前读取快照中按首收时间截断的历史窗口；设备绑定使用当前数据库快照。现有表没有完整的历史事务提交可见性和绑定变更时间线，因此它不是任意过去时刻的数据库重放器。模型离线评价应采用C独立、明确划分的数据与当时可用输入，不用这个接口补造过去决策。
