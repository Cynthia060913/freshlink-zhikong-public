# 短时预测输入守卫候选

本增量只为后续预测准备输入，不含模型、HTTP路由、页面、阈值评价、数据库写入或通知。无算法保底版保持应用来源4b9bd50、发布点1a2fa53及原制品字节。

`backend/app/modules/iot/forecast_window.py` 是纯函数模块。调用方显式提供设备、冷库、UTC决策时刻和窗口策略；只接收历史接口已有的标准化观测字段。仅当状态为`ready`时返回可供模型使用的不可变采样点；其余状态不提供模型点，更不代表“正常”。阈值规则选择、模型版本和告警语义仍需分别对接。

## 时间和数据边界

- 先按`received_at <= as_of`截断，再读取该观测采样/质量/温度字段；后来才到达的数据不能改变过去决策的输入状态或采样点。
- `sampled_at`也不得晚于决策时刻；设备与冷库必须同时匹配。仅消费已清洗、质量为`["ok"]`的标准化温度，不替C重新清洗原始载荷。
- 预测目标为`as_of + horizon`，不是最后一条迟到采样的时刻加horizon。保留采样/接收时间和观测ID，拒绝无时区时间。
- 独立检查样本数、采样跨度、最后采样时效和最大采样缺口。最新坏质量、非有限值、同观测ID改值均不能静默输出可用窗口。
- 相同观测重放幂等；按采样/接收/ID排序并限制交给模型的点数。调用方仍应使用已有查询上限，不传无界输入流。

默认策略仅是候选输入门槛：120秒历史、60秒目标、最新采样15秒内、至少8点/10秒跨度、单缺口最多10秒、最多360点。尚无算法实验支持这些数值作为最优参数；C的数据与对照验证完成后再确认，并保留参数版本。当前模块没有自动插值或把缺测补成真实采样。

## 本轮验证

- 缓存应用镜像的Python3.14.8、禁网且无数据库：13项专项通过，6个子用例通过；ruff检查/格式及新模块mypy strict通过。
- 复用A已录制的4b9浏览器33行快照（原CSV SHA256 `d274e282984100af525303cb1a5362bb96ccbd78b4b7cd5be74d80269ad4d47f`）。末次接收时刻最新采样年龄0.052423秒，但窗口存在超过候选10秒门槛的采样缺口，结果为`gapped_data`，没有模型点。按历史接收截断后，保留未来到达行与事先去除这些行所得状态/点一致；再过30秒为`stale_data`且无模型点。
- 录制样本不是独立训练/测试集，本轮没有拟合模型、计算预测成绩、取得提前预警收益或接入系统预测服务。仅守卫专项不代替应用全量回归或算法门禁。
