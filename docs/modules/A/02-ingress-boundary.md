# A1.1 遥测接收边界（独立实现，不是已上线 MQTT）

基线：main `a99c2a091204012891b8fa0c80e10b63087c57c1`。实现分支：`feature/a-ingress-protocol`。依照 RC1 提案建立可独立测试的 A 边界；三方共同契约仍待明确确认，本文件不替 B/C 签收。

## 已实现

`backend/app/modules/iot/ingress.py::receive_telemetry` 接收 topic、原始 bytes、可信设备上下文和服务器时间，返回接收封装，或带固定原因码/长度/SHA256 的拒绝异常。

- 校验注册、启用、绑定状态，以及精确的 `freshlink/v1/devices/{UUID}/telemetry` 主题和载荷身份。主题字符串本身不是认证；未来适配器必须先核验 broker 凭据/ACL，再从服务查询当前注册与绑定，不能从设备载荷构造可信上下文。
- 原包最多 32768 字节、JSON 容器嵌套最多 32 层。拒绝无效 UTF-8、非法 JSON、重复成员名、非标准 NaN/Infinity、非对象和未知 schema_version。错误元数据不含原包或攻击者主题；尚未实现有界审计存储/保留期。
- 原始 UTF-8 文本完全保留；每次读取 raw_payload 获得独立快照。缺 warehouse_id 只从可信上下文放入封装，不改原文；显式 null/不同仓库拒绝。设备自报 received_at 保留原文但不控制接收时间。
- received_at 必须由调用方服务器提供带时区时间并归一 UTC。每次网络接收生成新 reception_id；同一次数据库重试应复用封装，不重新调用。message_id 不改写，持久去重仍由 C 负责。
- 合法 JSON 中的错误采样时间/数值/单位不“修成正常”，交 C 的质量层决定并保留原始证据。指标数量/字段长度等 C 侧限制尚未在本模块代办。
