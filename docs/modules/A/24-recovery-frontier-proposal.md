## 2. 候选最小字段：按设备接纳，而非观测时间排序

以下是拟议内部元数据，不改变设备原始JSON、message_id、received_at、raw_text或
C观测ID，不让设备自行提供序号，不重写旧pending的稳定来源ID。

| 拟议项 | 所有者／含义 | 不允许的替代 |
|---|---|---|
| device_id + stream_epoch | A；本次明确的可信流世代，缺失旧世代不得默认完整 | 用重启时间自动清零 |
| admitted_seq | A；每设备已提交接纳的连续整数上界 | PG全局sequence/时钟/UUID排序 |
| admission_seq | A；接纳行的稳定序号，原reception重试复用 | 每次投递重新分配 |
| settled_through | A；已验证C持久终态回执的**连续前缀** | max(见过的终态序号) |
| evidence_revision / gap_state | A；坏证据/拒收/不确定性持久失效标记 | 用可裁剪audit历史作唯一门禁 |
| frozen_frontier | C；冻结时世代/序号/失效版本，与规则/批次/原异常绑定 | 只记最后观测时间 |

连续整数由同一设备行锁内的事务计数器分配，回滚不消耗已提交序号。不要使用可能
在回滚后留洞的全局`nextval()`当“无洞前缀”。同reception+相同指纹返回原序号；
reception重用指纹/设备改变，原关联和尝试关联都持久标不确定，不能覆盖原文。
不得把“队列删了”当作已保存终态；现有7天/1000条元数据裁剪也不能让坏证据消失
后自动判正常。检查点需持续保存或在无法证明历史时保守hold。

## 3. 三个原子边界与锁顺序

1. **接纳事务（A）**：检查可信注册/绑定；锁定设备流；检查reception幂等／冲突；
   同事务分配序号、保存原始信封、更新接纳上界；提交后才允许MQTT传输ACK。
   容量满／数据库失败不得ACK成业务成功；已知设备的持久拒收要更新不确定性状态。
   未知设备不凭消息自报device_id污染某个已注册设备。跨设备冲突按排序后的设备ID
   取得锁，禁止相反锁序。注册/解绑/世代改变的共享锁序也需一起审查。
2. **C调用与A检查点（A/C）**：C业务调用在A事务外；C先原子提交raw/reception/
   质量/相关作业才返回终态。A短事务重新验证原claim/指纹/租约后写终态元数据，
   只推进已覆盖的连续前缀；invalid/conflict也是有审计的终态，**不是正常样本**。
   C已提交但A崩溃时不推前沿，同原reception重放后再推进；旧claim不能覆盖新检查点。
3. **恢复冻结事务（共享集成＋C）**：要求同一PostgreSQL事务／同一连接持有与接纳
   兼容的设备锁，读取`admitted_seq == settled_through`、同世代/绑定/失效版本，
   核对C所见终态证据及恢复窗口，冻结规则/批次/原异常/来源ID并创建候选outbox。
   不是先检查A后在另一个事务调用C冻结。C接口如只接受Engine且自己begin，须先由C
   给出Connection/事务端口候选，不能由A用跨调用长事务或lambda“已全部提交”替代。

冻结门禁必须考虑并发入口：直接C摄取、修复工具、补投/重试等所有会改变该恢复窗口
的写入口，或者共用相同门禁，或者明确无法启用自动恢复。已有不受控C写入不因本
协议文字自动变安全。长C调用、broker重复投递及A单例queue_guard不等于设备前沿锁。

## 4. 晚提交／晚到数据与发送前复核

- 在冻结前已接纳但未提交C的任何行，必须使前缀门禁失败，包括早时间坏观测。
- 冻结后新接纳的晚到观测不得倒填进旧快照或被“只查冻结序号以前”默默忽略。
  如它可能影响原恢复窗口，保守失效尚未发送的候选；重新评价保留原证据，不自动
  复用已冻结旧正文发恢复。具体判定和新的来源ID规则由C/B确认，不能覆盖旧pending。
- 发给B前在短事务内重新核对冻结版本及有效性。已经开始的外部调用无法被后续
  数据原子撤回；必须定义清晰的发送线性化点和后续更正/再异常策略，不能声称
  任意迟到数据下“绝不曾出现过恢复”。没有这一约定时继续禁用自动恢复投递。
- 规则/批次/设备解绑切换也需同样使相关候选失效或在明确历史区间评价；设备
  正常不等于该仓所有批次正常，一个批次恢复不得清零另一批次历史暴露。

## 5. 实现前必须对拍的负向向量

| 场景 | 必须结果 |
|---|---|
| 序号1未终态、2已终态 | 前沿仍0，不冻结 |
| 原序号1重试／C提交后A崩溃 | 序号不变、不重复业务；重放前不推进 |
| 原claim过期后才返回／新claim已接手 | 不覆盖新A检查点，不据此跳前沿 |
| 同时接纳与冻结 | 单一锁序下线性化；冻结不能略过已先提交接纳 |
| 同接收时间不同UUID／后来接纳早时间坏行 | 无UUID排序假设；hold或失效旧候选 |
| invalid/conflict／跨设备ID重用 | 终态可推进完整性，但坏证据阻挡恢复；双方hold |
| 队列满、重试耗尽、缺表、元数据裁剪、旧世代无检查点 | 明确hold/失败，不自动归零正常 |
| 两设备／两仓／同仓两批 | 设备不互相长期饿死，批次评价独立、旧证据保留 |
| 冻结后晚到且影响旧窗口／发前绑定变化 | 未发送候选不投递；已发送走显式更正策略 |

这些是待实现/待实跑向量，**本说明没有把它们写成通过**。现有用例、FIFO六项与
C坏证据四项只是对应已实现边界的分段证明。
