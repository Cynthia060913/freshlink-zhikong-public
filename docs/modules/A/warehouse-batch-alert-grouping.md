# 冷库与批次告警归组

## 使用范围

首页按冷库与批次汇总现有告警记录，帮助值班人员定位记录较集中的批次。
待处理、已确认、机器判定已恢复分别计数；已确认仍可能未恢复。
排序先按待处理与已确认记录之和降序，再按最近入库时间及归属标识排序。
数量属于历史记录累计，不是独立事故、当前异常设备、果品损失或品质评分。
同一来源重复提交由原幂等接收逻辑处理；不同来源的关联更正仍为独立追溯记录。

## 数据与接口

- `GET /api/v1/alerts/groups?skip=0&limit=12`：需要原有有效登录，权限与告警列表相同。
  一条数据库查询返回分页、分组总数及各组状态计数，避免仅统计列表首页。
- `GET /api/v1/alerts/` 增加 `warehouse_id`、`batch_id` 精确筛选，兼容原分页、状态和级别筛选。
  未关联归属使用 `unassigned_warehouse=true` 或 `unassigned_batch=true`，不能把空归属当成无筛选。
  同时提供具体 ID 和对应未关联标志返回422。
- 前端点击分组后查看对应原始记录，可继续按状态筛选和翻页，并读取原状态迁移历史。
  分组与明细各自实时查询，不能声称两次请求属于同一快照。
- 仅统计原告警处置列表中的异常类型；设备连接、恢复事件本身不重复计入。
  设备离线及故障仍从设备管理查看，不借分组宣称所有异常都已覆盖。

不添加数据表、迁移、告警归并写入、模型或派发器。不变更阈值、确认、恢复、通知及控制流程。
读取失败或30秒无有效刷新撤下数量，空列表不代表环境正常。

## 本轮验证

2026-11-03，本机临时PostgreSQL经正式迁移及metadata检查后，8项分组专项与62项原告警、恢复、更正回归通过。
专项覆盖超过100条记录的完整计数、跨冷库同名批次、空归属、状态分项与原列表一致、分页越界、参数拒绝、未登录拒绝、数据库读故障503及查询无写入。
前端规范、TypeScript及构建通过，接口客户端使用原生成器更新。

独立临时库与浏览器准备两库三批的模拟候选记录，通过原候选接收、确认与恢复服务建立状态；
三组共15条告警记录，其中第一组12条为10待处理、1已确认、1已恢复。
浏览器已核10+2翻页、状态筛选、来源和迁移记录、390像素无横向溢出、匿名401、普通用户200及读失败撤值。
重复来源未增加分组数。浏览器操作前后原记录及计数相同。

以上为本机候选验证；模拟候选记录不冒充本次从原始传感器异常到外部通知的完整E1。
未新发真实通知，未修改原数据库；不代独立审查、第二机、main合并或正式投稿结论。
