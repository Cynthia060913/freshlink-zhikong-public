# 现有设备页的单目标温度预测参考

本增量在原设备管理、遥测清洗、历史查询、告警和控制之上增加只读计算。
巡检人员可从温度设备详情查看下一分钟的温度估计，并与末值和线性趋势对照。
输入来自同设备、同冷库已经提交的清洗观测；所有结果保留观测ID和计算时刻。

## 实现与边界

- `iot/forecast_observations.py` 通过只读一致性事务读取原C存储，不新增表或迁移。
- `iot/forecast_window.py` 先按接收时刻截断，再核归属、质量、时效、缺口和点数。
- `iot/forecast_preview.py` 调用C纯计算函数，固定120秒历史与60秒目标。
- `iot/forecast_assets/c-ridge-v1.json` 是C已交付参数的逐字节副本；加载上限64KiB，
  规范化参数SHA256必须为 `631c342435be05626f4ddafc648984091d9a317a803ffe2ee652d324ab5a7ec8`。
- C来源为 `34cad612dde789c85d257963b3dc3c2754f1bfad`，算法位于
  `telemetry/forecast_candidate.py`；接口兼容返修没有改变模型或实验参数。
- `DeviceForecastPanel.tsx` 在已有设备详情内显示历史实线、一个未来预测点及三种估计。
  单点不作为多步曲线；HTTP失败、数据过期或不可用时撤下旧估计。

默认 `FRESHLINK_FORECAST_PREVIEW_ENABLED=false`，未开启时页面不展示实验入口。
查询使用现有登录鉴权，决策时刻取服务器时钟，冷库归属取注册设备；请求参数不能改写。
未就绪时返回明确原因，不返回正常风险结论。模型缺失、损坏、参数变更均保守不可用。
此服务没有通知、业务状态更新、自动恢复或设备控制调用。

认证接口：

- `GET /api/v1/devices/forecast-preview/status`
- `GET /api/v1/devices/{device_id}/temperature-forecast`

响应含输入ID、采样/接收时刻、决策/目标时刻、过期时刻、模型/参数/策略版本。
当前页面只用于实验性预测参考；原阈值告警仍按原流程运行。

## 独立离线演示

新优化候选的离线包可显式选择预测预览。原包不因本工具改动而升级；
必须使用实际包含本增量且来源核验通过的新应用。

```powershell
./scripts/windows/open-offline-demo.ps1 -Kit '<离线工具目录>' -ExpectedManifestSha256 '<该清单的SHA256>' -ExpectedSource '<新应用完整源码SHA>' -ForecastPreview -Start -Minutes 5
```

该选项只进入本次随机命名演示项目的环境，不写原配置。按既有说明登录并打开
温度设备详情，展开“查看短时预测”；有效观测不足或采样不连续时先显示不可用原因。
通过已有受限停机工具结束本次演示，数据库和证据按既有交付约定保留。

## 正式纳入优化包的出口

1. 按说明能启动并操作，页面和报告能够解释输入、处理、输出、用途与局限。
2. 固定模型、数据规则/样本/划分及命令能够复算；数值按报告容差核对。
3. 观测到模型再到页面的实际调用可追溯，原业务保持，C完成独立验收。
4. 关联源码、可运行应用、算法报告/实验数据、设计增量、PPT和视频来源一致。

只有上述出口齐备才纳入新的优化包，无算法封存版独立保留。
