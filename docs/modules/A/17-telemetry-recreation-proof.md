## 这次实际检查什么

A08 已验证运行器重启、C 暂时失败和丢终态回执。本入口进一步使用**真实容器替换**：
先退出准备进程，替换 PostgreSQL 与 Mosquitto 两个容器，仅保留两个明确创建的合成卷；
再由新进程、新连接和新接收器恢复，不把 Python 内存或旧容器文件系统当持久层。

准备阶段先重跑 A07/A08。之后真实设备账号发布一个包：A 保存原文/可信 envelope，
确认 QoS1，投递器领取第1次租约后故意退出，C 此时未收到该包。接收器离线后设备
再发布一个不同消息，Broker 接受，但 A 数据库中没有它。此时只是准备好，未宣称恢复。

容器替换后，入口实际比较两个容器 ID 已变化、挂载卷名称不变；新进程确认 PG 启动时间
变化，同时读到原 A reception ID／原文摘要／可信接收时间／租约 ID／截止时刻／尝试1。
MQTT 新连接必须返回 `session_present=true`，再收到离线期间的第二包；resume 阶段没有
运行发布者，不能通过重新发包伪造 Broker 恢复。按真实租约时间投递到固定 C，原租约
从第2次继续而不是重置为1。两原文都在 C 接收表回读匹配，新增观测/接收/终态记录各2，
未解决原包归零。不会因恢复而生成第二条同设备消息的业务观测。
