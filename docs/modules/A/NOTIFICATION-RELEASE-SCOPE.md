# 通知发行入口的收件范围

当前参赛场景使用一个明确同意收件的本人邮箱与一个飞书验收群，两个独立渠道均须
具体授权和终端实收。多邮箱部分拒收后的自动补发不属于本次必选场景，不能在尚无
完整持久化收件人状态时悄悄启用或宣称全部送达。

A的显式 `notification_service` 入口在 `--send` 且配置SMTP时只接受**一个**邮箱；
空名单、多个邮箱或重复地址都在创建数据库连接/进入provider worker之前拒绝，
固定脱敏错误返回2。单邮箱行为、默认dry-run、飞书独立渠道保持原来语义。
dry-run仍允许预览原有最多20个收件配置，不产生发送；不添加绕过发行护栏的开关。
这是A入口候选增量，不修改B的适配器/派发器或原数据库。

此护栏只界定已验证的发行范围，**不解决**单邮箱DATA接受未知且attempt写失败后的
重发风险；B的持久意图/hold及故障回归仍须独立修复审查。B低层多收件人结果也不能
伪称全部接受；如保留低层调用，必须明确其候选范围，不能将入口护栏当作通用适配器
全部正确的证明。

普通配置、dry-run和`--send`开关都不替代收件者同意或具体发送批准。本改动没有
实际发送。若纳入最终业务镜像，必须记录新来源并按改动验证，不能重标旧E1为新实测。
