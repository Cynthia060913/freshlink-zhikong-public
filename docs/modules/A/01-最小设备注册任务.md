## 字段提案

| 字段 | 约束和含义 |
|---|---|
| id | 服务端生成 UUID，唯一设备标识 |
| code | 规范化后唯一的设备编号，非空，有明确长度限制 |
| name | 显示名称，非空，有明确长度限制 |
| kind | temperature_sensor 或 cooling_actuator；后续湿度、门磁、电表通过显式枚举扩展 |
| warehouse_id | B 维护的冷库 UUID；本任务允许未绑定，不能假造冷库或提前创建 B 的表 |
| is_simulated | 首版 true，明确设备来自软件仿真 |
| last_seen_at | 尚未接入心跳时为 null，不接受用户凭注册请求伪造在线 |
| created_at | 服务端 UTC 有时区时间，响应带时区 |
| connectivity | 首版从 last_seen_at 派生 unknown；后续心跳模块加入 online/offline 判定 |

注册设备不等于设备在线或运行正常。暂无心跳显示“未连接/未知”，不能显示已在线。未知冷库关联如何校验须等 B 的只读接口落实；A-01 只接受未绑定注册，拒绝非空 warehouse_id，不静默接受无从验证的冷库。

## API 提案

- POST /api/v1/devices：管理员注册，成功 201，返回公共设备信息；重复规范编号 409；类型/长度/非法 UUID 等 422；非管理员拒绝，未认证拒绝。
- GET /api/v1/devices：认证只读，skip/limit 范围受限，返回 data 和 count，稳定排序；空列表明确 data=[]、count=0。
- GET /api/v1/devices/{device_id}：认证只读，未知设备 404，非法 UUID 422。

不提供公开无鉴权注册、假心跳接口或强制删库脚本。不在响应里放密码/接入秘密。重复编号异常须回滚事务，随后列表仍可正常查询。

## 必须检查

1. 模块可导入，元数据含设备表，迁移从当前版本升级和从空库升级可行。
2. 管理员注册温度设备/制冷执行器；列表/详情与数据库一致；重启后仍在。
3. 重复编号返回冲突；非法类型、空名称和长度边界拒绝；不同大小写/空格规范规则明确。
4. 无登录、非管理员注册拒绝；活动普通用户只读；未知 ID 404。
5. 初次注册 last_seen_at=null、connectivity=unknown，不冒充在线。
6. 非空 warehouse_id 在 B 接入前明确拒绝；UTC 输出带时区。
7. 原模板登录仍通过。测试只清理自身测试对象或独立测试库，不破坏用户数据。
