这是显式库函数与真实 PostgreSQL 回归，不是发布、生产操作或 E1 签收。

## 使用边界

`initialize_fresh_streams` 接受调用方同一个 PostgreSQL READ COMMITTED 外层事务、
活跃管理员身份、明确的 1—14 个采集设备/实际冷库绑定和逐设备 UUID epoch。
它不建表、不迁移、不启动 worker、不改历史、不清除 hold、不轮换已有 epoch，
没有 HTTP、CLI、启动钩子或自动调用点。原应用数据库未运行该函数。

先取得 A inbox 单例、完整证据表集合及排序后的设备行锁；必须存在当前 C 全部
十张证据表、A04/A05 实际表和 B 告警表。未知 telemetry 表也拒绝，不能用缺表
或测试 DDL 冒充已审定迁移。新增 C 表时必须先重新核对本清单。

首次初始化要求所有 A/B/C 证据为空，设备是真实注册温度传感器、绑定实际 B 冷库。
全部验证后才插入 origin_verified、显式 epoch 和零计数；提交/回滚完全由调用方负责。
同范围同 epoch 重试返回已有起点，不修改 hold、序号或证据版本，也不是健康证明。
部分范围、换 epoch、未验证起点和已有历史均拒绝，不能把它当数据修复工具。

调用前必须停止未经审定的旧写入器。锁顺序为 inbox 单例→证据表→排序设备行，
不得从已持 stream 锁的 C 写事务反向调用。运维调用方还需配置有限锁等待/事务超时，
在外层提交后留脱敏审计；本函数的身份检查不等于已实现独立持久操作审计。
