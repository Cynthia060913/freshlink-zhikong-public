**不使用假 UI 截图**；演示动作只指向真实页面、代码或已渲染图件。恢复端口、

## 第 1 页 冷库业务与角色范围

- 讲稿（约 40 秒）：「系统面向两座苹果冷库、三批同品种苹果，用软件模拟七个测区，
  每区一个温度采集身份和一个制冷执行身份，一共十四个逻辑设备。数据来自仿真，不是
  实物果品实验。A 负责设备注册、在线、控制回执和数据链接线；B 负责冷库批次、规则、
  告警和追溯；C 负责清洗、历史、快照 CSV 和评价。」
- 演示动作：打开设备注册/列表页，展示已注册设备与两库三批绑定；口头指出 A/B/C 分工。
- 已证据支持：A35 `8cd5f2d` 十四身份真实心跳、执行 ACK 后降温。
- 待实测/不能说：不声称实物品质实验或真实腐败概率。

## 第 2 页 共享系统架构与模块归属

- 讲稿（约 40 秒）：「这是共享系统架构。展示层 React 加 FastAPI，总入口只挂一次 API
  前缀；A 入口做注册、心跳、MQTT 接纳、控制回执和向 B 投递；B 做规则告警；C 做数据
  质量；底层是 PostgreSQL 和 Mosquitto。图里的通知实收是虚线，还在等真实授权。」
- 演示动作：展示 `tikz_architecture.png`，口头标注分层与 A/B/C 归属。
- 已证据支持：分层见 A-SYSTEM-DESIGN §2；架构图已实际编译渲染（design/README.md）。
- 待实测/不能说：图中组件存在不等于后台调度已启用；两通知实收为虚线待验收。

## 第 3 页 控制与数据链的分段证据

- 讲稿（约 45 秒）：「控制链是注册、在线、下发命令、设备执行 ACK，再看后续温度。数据
  链是 raw、清洗、历史，再到同筛选 CSV。右侧是分段证据：ACK 后降温、CSV 对拍、十四
  身份心跳都已经跑过；但正式恢复端口、F03 更正、完整 E1 还没完成，这三项不写通过。」
- 演示动作：控制页下发一条命令 → 展示设备 ACK → 遥测页看温度下降 → 导出同筛选 CSV
  并核对 ID；停发后展示离线、重启后恢复。
- 已证据支持：A46 `62bb2ef`、A35 `8cd5f2d`、A55 `ecf19d0`。
- 待实测/不能说：正式恢复端口与 F03 更正接线、同一冻结版完整 E1、两渠道终端实收。

## 第 4 页 可靠性与真实验证边界

- 讲稿（约 40 秒）：「可靠性方面我们做了事务回滚、持久接纳、固定快照，还有合成派发的
  重启恢复：attempt 从 0 到 2 到 3 到 3，重启只补缺失、不重复发。但这是合成 SMTP 和
  APP，不是真服务，更不是手机和邮箱实收。」
- 演示动作：对照简表逐行指出「实际证明」与「不代表什么」两列。
- 已证据支持：A54 `1b7a9d9`、A55 `ecf19d0`、A46 `62bb2ef`。
- 待实测/不能说：合成派发不是真服务；两渠道实收、完整 E1、第二机均未签收。
