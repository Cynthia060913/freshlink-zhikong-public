## 一、需求与边界

系统面向两座苹果冷库、三批同品种苹果，软件模拟七个测区，每区一个温度采集身份
与一个制冷执行身份，共十四个逻辑设备。主要操作：注册并绑定设备、查看在线状态、
持续查看原始/清洗数据、查询同筛选历史与 CSV、下发制冷命令、核对设备执行 ACK 与
后续温度、处置异常并保留追溯。通知须 SMTP 与飞书手机端两个独立渠道授权实收，
服务接受不等于终端实收。模拟数据不是实物果品实验，阈值异常不宣称为真实腐败概率；
算法是可选加分项，本材料不涉及。项目不要求采购硬件或付费服务器，交付用软件模拟
与隔离容器验证。

## 二、实际分层

- 展示层：React/TypeScript/Vite，公共认证与导航，设备、控制、B 告警、C 数据页面。
- HTTP 层：FastAPI，总入口只在 `backend/app/main.py` 加一次 `settings.API_V1_STR`，
  子路由复用公共登录权限。
- 感知/执行层：`simulator_runtime.py` 与 `simulator_fleet.py` 七测区监督器；每设备
  独立身份与 MQTT ACL，逐测区 SQLite 只保存模拟器本地执行状态，不是服务器业务库。
- A 服务层：设备注册、心跳与在线离线、控制事务及回执、MQTT 接纳与持久收件队列、
  有界租约与重试、A→B 设备事件投递。
- B 服务层：冷库、批次、版本化规则、异常事件、状态变化与通知 attempt。
- C 服务层：观测 raw 与质量、历史、固定快照分页与 CSV、评价、outbox 与恢复进度。
- 存储层：PostgreSQL 保存设备/控制/A 队列与 B/C 业务；Mosquitto 做设备消息路由。

进程启动不等于全部 worker 已运行；容器、进程与数据库需分别验证，不能只靠网页打开验收。

## 三、设备与控制的完整数据链

遥测链：设备温度消息 → A 校验身份/绑定并持久接纳 → C 同事务保存 raw/质量/观测 →
历史页面与同快照 CSV → 调用方选择 B 生效历史规则 → C 门禁候选与持久 outbox →
B 摄取接口接受、来源摘要回读与追溯 → 已提交事件通知派发 → SMTP 与飞书终端分别实收
（末两步仍未签收）。

控制链：登录用户下发 → 持久命令/尝试 → MQTT 执行设备 → 设备事务保存执行结果并
返回原 ACK → 服务端回执 → 后续温度采样反映制冷效果。仅创建命令、MQTT publish 成功
或页面显示“发送”都不能写成已执行；设备 ACK 之后有新的温度数据才称执行闭环。

## 四、事务、权限与故障追溯

A 提供的 `begin_evidence_write` 要求 C 使用同一调用方 Connection 在写前取得同设备门禁、写后
保存冻结戳；没有覆盖所有写入口就不能启用自动恢复。通知派发不放在持数据库锁的事务内。
A 保留原异常行锁、锁后重读、单调状态时间、事务失败回滚与 HTTP 503+Retry-After。
设备采用逐设备账户/ACL，生产默认 TLS。登录权限、摄取权限、设备身份与通知收件授权
分别验证，不互相替代。异常恢复要求完整可信窗口、关联原异常、重放/并发安全与晚到
证据处理；不完整或停机缺口不能判正常，恢复关闭异常也不删除原始超温与历史暴露。

## 五、实际迁移链与关键实体

共同源码唯一迁移链为 A03→B01→A04→A05→C01，C01 是唯一 head，不是平行建表。在专属
空库实际升级并通过 model check 后，只读反射得到 33 张表；三张 ER 图仅展示 19 个核心
实体与 17 条已逐项核对真实外键的边，完整字段见数据字典
`docs/submission/design/DATA-DICTIONARY.md`，边见 `docs/submission/design/er-edges.json`。
关键关系：心跳/冲突/在线事件和 `iot_command` 通过外键引用 `iot_device`，其中命令
设备外键删除策略为 RESTRICT；`iot_command_attempt`/`iot_command_receipt` 引用
`iot_command`，删除策略为 CASCADE；
`alerts_warehouse → alerts_batch → alerts_batch_rule_snapshot`；
`alerts_event → alerts_status_transition`/`alerts_notification_attempt`；
C 质量、接收/评价、outbox与快照成员按边清单中的外键关联到观测；
接收重用审计行关联原接收记录，不能把父子关系图箭头反称为外键引用方向。
`iot_device.warehouse_id`、C 观测的设备/冷库 UUID、outbox 与 B 来源等属业务逻辑引用
而非数据库外键，不按字段同名擅自补线。这些表由三人各自模块共建，33 表并非全为 A
开发。架构图、设备控制 ER、仓储告警 ER、观测快照 ER 四图见
`docs/submission/design/tikz_architecture.png`、`tikz_er_a.png`、`tikz_er_b.png`、
`tikz_er_c.png`，均为实际编译渲染；最终冻结版若有模式变更须重新反射与出图，不能只
替换 SHA 标签。
