**基准**：共同 main `319aa63`（= 一库 E1 实测来源 `e7fffd61`，全 Git 树
一致；录制前按冻结版刷新精确 SHA 并记录）。
**原则**：只录真实页面与真实操作；未完成的能力（真实通知终端实收）**不出镜
冒充完成**，需要时用"服务接受 ≠ 终端实收"的口播说明。

**凡 UI 没有的入口一律不录**；相应能力改以"API / 测试证据"口播带过（见第 2 节）。

## 0. 录前准备（A 负责环境）

- 同版运行包（M02 候选）+ PostgreSQL + Mosquitto 已启动；两库三批数据已注入。

## 1. UI 可直接演示的段落（B 页面段，预计 3 分钟）

1. **登录 → 设备管理页**
   - 展示 14 台设备与两冷库（WH1/WH2）归属（页面真实存在；导航只有
     Dashboard、Items、设备管理、遥测历史、告警处置，**没有独立的
     "冷库/批次总览"入口**）。
   - 口播：两库三批十四个逻辑仿真设备（七测区，每区采集+执行两个身份）；
     批次归属关系**不在本段页面演示**（Items 页是模板条目 CRUD，不是
     批次业务页面，不做不存在的点击），由接口响应/数据库查询的既有
     测试证据支撑，口播一句带过。
2. **告警列表页**
   - 使用**状态筛选**（待处理 / 已确认 / 已恢复）切换一次，再使用
     **级别筛选**（提示 / 警告 / 严重）切换一次——演示两个真实存在的筛选器。
   - 展示列表列：类型/级别、观测值、采样时间、状态、来源 ID。
   - 口播：来源 ID 稳定可追溯；页面加载失败会提示重试，**查询失败不解释
     为没有告警**（页面自带该提示文案）。
3. **告警详情弹窗（核心段）**
   - 点某条告警的"查看 / 处置"：展示**当前状态**、**告警事件 ID**、
     **状态迁移记录**（每条 from → to、时间、触发来源）。
   - 口播：迁移记录只追加、不删除；告警行不可变，历史暴露保留不清零。
4. **人工处置（ACK）——管理员视角**
   - 用管理员账号对一条**待处理**告警点击"确认告警"，展示成功与状态变化。
   - 对**已恢复**的告警打开详情——按钮置灰不可点（页面文案："仅'待处理'
     可确认；已恢复的告警不能回退确认"）。
   - 口播：重复确认是幂等的——第二次调用不会产生第二条迁移记录
     （接口行为，测试覆盖，见下节）。
5. **权限**
   - 切换普通用户账号打开同一详情——页面显示"当前为只读访问；确认操作
     仅限管理员"，无确认按钮。
   - 口播：普通账号在服务端同样被拒（403），不只是前端隐藏按钮
     （接口回归测试覆盖）。

## 2. 不在 UI 出镜、以 API / 测试证据口播的能力

以下能力 UI 当前没有入口或不可交互，**不录画面、不假装点**，口播一句
"由接口与自动化测试证据支撑"即可：

- **批次维度筛选 / 更正关联展示**：列表暂无批次筛选；data_quality 更正的
  "关联原异常"双 ID（`related_source_event_id`）在接口响应与数据库中可查
  （口播：晚到坏证据以更正追溯，不改写历史，原状态不被重开）。
- **ACK 幂等与 409**：对已恢复告警调 ACK 返回 409 且零状态迁移；
  重复 ACK 返回既有状态、不写第二条迁移——由 lifecycle 接口测试覆盖。
- **payload / 规则快照明细**：事件行不可变，内容摘要与规则快照 ID/版本
  存于事件表；展示属于接口/数据库证据，非页面弹窗内容。
- **通知尝试审计**：每渠道 attempt（渠道、结果枚举、时间、不含敏感信息的
  安全错误码）记录在 `alerts_notification_attempt` 表；dry-run 不产生
  attempt 行。口播（如实）：**当前演示环境为 dry-run/未配置真实渠道，
  不展示发送画面；双渠道终端实收已由队长本人在一库同版同事件 E1 中
  确认（#6 6459911129，邮件与手机飞书均收到、来源 ID 一致），该事实由
  A 的 E1 实测记录呈现，不在本 B 段画面里冒充。**
