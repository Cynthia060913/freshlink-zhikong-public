## 1. 建议操作顺序（B 页面段，预计 3–4 分钟）

1. **登录 → 冷库/批次总览**
   - 展示两冷库（WH1/WH2）、三批同品种苹果的归属关系。
   - 口播：两库三批十四个逻辑仿真设备（七测区，每区采集+执行两个身份）。
2. **告警列表页**
   - 按批次筛选（多批场景下不任选第一批，体现 F02 生效历史规则）。
   - 展示告警 kind（温度高/低、数据质量、设备离线/故障）与当前状态
     （open / acknowledged / resolved）。
   - 口播：来源 ID 稳定可追溯；列表状态由 append-only 迁移表推导。
3. **告警详情页（核心段）**
   - 展示单条温度高告警的追溯字段：来源事件 ID、内容摘要、规则快照 ID 与
     版本（强调：**引用历史规则，不用今天的新规则覆盖过去**）、证据。
   - 若库中有 data_quality 更正记录：展示"关联事件"双 ID（更正 → 原异常），
     口播：晚到坏证据以更正追溯，不改写历史，原状态不被重开。
4. **人工处置（ACK）**
   - 对一条 open 告警执行确认；重复点击第二次——页面/接口仍幂等，不产生
     第二条迁移。
   - 对已 resolved 的告警尝试 ACK——展示拒绝提示（口播：append-only，
     已关闭不重开）。
5. **恢复展示**
   - 展示一条由机器判定恢复关闭的告警：迁移历史 open→acknowledged→resolved
     （或 open→resolved），原始超温记录与历史暴露保留不清零。
6. **通知尝试记录**
   - 打开通知/尝试记录视图：同一业务事件可查到每渠道 attempt（渠道、结果、
     时间、安全错误码）。
   - 口播（如实）：**当前演示环境为 dry-run/未配置真实渠道，此处显示的是
     尝试审计与"服务接受"语义；真实邮件/飞书终端实收需持有人配置并经
     授权后另行演示，不在本段冒充。**
7. **权限**
   - 用普通只读用户尝试 ACK/越权操作——展示拒绝。
