# 03 真实界面操作卡（8—10 张，供录屏/验收与 B 汇编）

软件来源 `bfb2c927f2a1a083ac21996844d38ac4eb4abbef`。页面路径、按钮/字段名均取自当前
`frontend/src/features/{devices,telemetry,alerts}/` 与路由源码；**未经浏览器实跑**，每张卡
一律标"按源码核对/待现场验证"，不把源码存在写成已点击通过。设备绑定、仓库/批次无页面
入口（见卡片 11 说明）。

## 卡 1 · 登录进入（管理员/普通用户）

- 前置身份：已有账号（演示 `admin@example.com`，密码读本机 `.env.freshlink`）。
- 页面路径：`/login`（未登录访问 `/_layout` 会重定向到 `/login`）。
- 操作：输入邮箱、密码 → 点击"登录"按钮（`frontend/src/routes/login.tsx`）。
- 预期：进入 `/`（Dashboard）；侧栏显示 设备管理/遥测历史/告警处置；管理员额外显示 Admin。
- 截图建议：登录后首页 + 侧栏完整项。
- 源文件：`frontend/src/routes/login.tsx`、`components/Sidebar/AppSidebar.tsx`。

## 卡 2 · 管理员注册设备

- 前置身份：管理员（`is_superuser`）；普通用户看不到注册表单。
- 页面路径：`/devices`（设备管理）。
- 操作："注册设备"区块填写 设备编号（字母数字下划线/连字符）、设备名称、设备类型
  （温度测点/制冷执行器）→ 点击"注册设备"。
- 预期：绿色提示"已注册 …；尚未收到心跳，不能判定在线"；列表刷新显示该设备；重复编号报错。
- 截图建议：注册前表单 + 成功提示 + 列表新增行。
- 源文件：`frontend/src/features/devices/DevicesPage.tsx`（`register`、`deviceError`）。

## 卡 3 · 普通用户只读设备列表

- 前置身份：普通用户（非 `is_superuser`）。
- 页面路径：`/devices`。
- 操作：直接打开设备列表；无注册区块，显示"当前为只读访问；管理员可注册设备。"。
- 预期：可看列表与详情，不可注册；分页"上一页/下一页"可用。
- 截图建议：只读提示文案 + 列表。
- 源文件：`DevicesPage.tsx`（`user?.is_superuser` 分支）。

## 卡 4 · 设备详情与连接状态/连接事件

- 前置身份：任意已登录用户；设备已注册。
- 页面路径：`/devices` → 某行"查看详情"。
- 操作：点击"查看详情"打开设备详情对话框；查看 连接状态（在线/离线/未连接·未知）、
  冷库（warehouse_id 或"未绑定"）、最近心跳；下滚看"最近连接事件"。
- 预期：事件行显示"心跳超时离线"/"连接恢复"、来源 ID、关联离线 ID、投递状态。
- 截图建议：详情字段 + 连接事件列表。
- 源文件：`DevicesPage.tsx`、`features/devices/connection.ts`（`connectionLabel`）。

## 卡 5 · 远程制冷控制与设备回执（ACK）

- 前置身份：管理员；目标设备为 制冷执行器、已绑定冷库、`connectivity=online`、无未结束命令。
- 页面路径：`/devices` → 查看详情 → "远程制冷控制"。
- 操作：选 控制动作（开启制冷/关闭制冷）→ 命令有效期（30/60/120 秒）→ 点击"准备下发" →
  确认框点"确认下发开启制冷"；随后"最近 5 条命令"点"查询此命令"看回执。
- 预期：出现"待确认命令"编号；命令状态按 排队中/已发送/设备回执：执行成功 变化；回执区分
  "MQTT 接受（不是执行确认）"与"有效回执接收"；迟到/冲突回执单列提示。
- 截图建议：确认框 → 命令列表 → 回执详情（含"MQTT 接受"与"有效回执"两行）。
- 源文件：`features/devices/DeviceControlPanel.tsx`、`features/devices/control-api.ts`
  （`commandLabels`）。**禁用 ACK 按钮不写"再点一次验证幂等"**：后台幂等（G3）与界面操作分开。

## 卡 6 · 遥测历史筛选与固定快照

- 前置身份：任意已登录用户；已有观测数据。
- 页面路径：`/telemetry`（遥测历史）。
- 操作：填 设备 ID / 冷库 ID / 采样起始 UTC / 采样结束 UTC / 接收起止 / 质量标记 → 点
  "按筛选新建快照"；"刷新快照"在不改筛选时重建快照。
- 预期："最新已存观测"显示接收/采样 UTC、温度 °C、质量标记、候选风险；列表显示
  "固定快照共 N 条"，分页走同一快照。
- 截图建议：筛选表单 + 最新观测 + 列表表头（采样/接收/设备/温度/湿度/质量风险/规则版本）。
- 源文件：`features/telemetry/TelemetryPage.tsx`。

## 卡 7 · 导出同快照 CSV

- 前置身份：同卡 6。
- 页面路径：`/telemetry` → 列表右上"导出本次快照 CSV"。
- 操作：建立快照后点击该按钮，浏览器下载 `observations.csv`。
- 预期：CSV 与当前分页来自同一 snapshot_id，行/值/单位一致；导出失败显示错误文案。
- 截图建议：下载的 CSV 打开 + 列表页同屏（ID 对拍）。
- 源文件：`TelemetryPage.tsx`（`download`）、`features/telemetry/api.ts`（`csv`）。

## 卡 8 · 观测原始证据与接收记录

- 前置身份：同卡 6。
- 页面路径：`/telemetry` → 列表某行"查看"。
- 操作：点击"查看"打开"观测原始证据"。
- 预期：显示质量标记、`raw_text` 原文、关联接收次数；有冲突/无效接收时显示红色提示，
  说明"风险只对应原观测，不能把冲突数据判为正常"。
- 截图建议：raw_text 区块 + 接收记录（首次保存/重复接收/消息冲突/无效数据）。
- 源文件：`TelemetryPage.tsx`（`detail` 分支）。

## 卡 9 · 告警列表筛选与关联原事件

- 前置身份：任意已登录用户。
- 页面路径：`/alerts`（告警处置）。
- 操作：用 状态（全部/待处理/已确认/已恢复）与 级别（提示/警告/严重）筛选；点"刷新"。
- 预期：列表显示 类型/级别、观测值、采样时间、状态、来源 ID、关联原异常 ID；分页可用。
- 截图建议：筛选控件 + 列表行（含 source_event_id 与 related_source_event_id）。
- 源文件：`features/alerts/AlertsPage.tsx`、`features/alerts/api.ts`（`stateLabels`）。

## 卡 10 · 告警查看/处置与状态迁移（管理员 vs 普通用户）

- 前置身份：管理员可"确认告警"；普通用户只读。
- 页面路径：`/alerts` → 某行"查看 / 处置"。
- 操作：打开处置对话框看"状态迁移记录"；管理员对"待处理"告警点"确认告警"。
- 预期：状态迁移记录追加显示（待处理 → 已确认 → 已恢复（机器判定））；已恢复告警点确认报
  409 提示"不能再确认"；普通用户显示"确认操作仅限管理员"。
- 截图建议：迁移记录列表 + 确认按钮区。
- 源文件：`AlertsPage.tsx`（`acknowledge`）、`api.ts`（`stateLabels`、`alertError`）。

## 卡 11 · 说明：仓库/批次无页面入口

- 设备页只显示 `warehouse_id`（"未绑定"），**无绑定按钮**；冷库/批次/规则由后端 B 模块
  API 与初始化准备（R10）。`/items`、`/admin` 是上游模板示例页，不是冷链仓库/批次业务。
- 录屏/验收需说明"两库三批由初始化/API 准备，界面无对应管理页"，不编造页面。
- 源文件：`frontend/src/routeTree.gen.ts`（路由全集）、`components/Admin/*`、`components/Items/*`。
