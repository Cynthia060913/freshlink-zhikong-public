建议节奏，不是赛事强制时长。每个镜头列 画面、操作、应出现结果、来源、目前能否录、缺口及

  身份 + 一个制冷执行身份 = 14 逻辑设备。
- 应出现结果：页面出现"软件仿真设备"提示与设备列表；讲清"不是实物果品实验"。
- 来源：`frontend/src/features/devices/DevicesPage.tsx`（顶部提示）；`docs/submission/A-SYSTEM-DESIGN.md` §1。
- 目前能否录：能（源码已核对，浏览器待现场）。
- 缺口：无。

## 镜头 2 · 设备注册与在线状态（约 45 秒）

- 画面/操作：`/devices` 注册设备 → 列表查看连接状态与"查看详情"的最近连接事件。
- 应出现结果：注册提示"尚未收到心跳，不能判定在线"；连接状态 在线/离线/未连接·未知；事件含"心跳超时离线/连接恢复"与来源 ID。
- 来源：`DevicesPage.tsx`、`features/devices/connection.ts`。
- 目前能否录：待现场验证（页面源码已核对，未浏览器实跑）。
- 缺口：bfb 级在线/离线同版实跑未复验（A）。

## 镜头 3 · 数据清洗与历史 CSV（约 50 秒）

- 画面/操作：`/telemetry` 填筛选 → "按筛选新建快照" → 看列表 → "导出本次快照 CSV" → "查看"原始证据。
- 应出现结果：最新观测显示温度/质量/风险；列表"固定快照共 N 条"；CSV 与分页同快照一致；raw_text 保留、冲突/无效接收有红色提示。
- 来源：`frontend/src/features/telemetry/TelemetryPage.tsx`。
- 目前能否录：待现场验证（需真实观测数据 + 浏览器）。
- 缺口：同版浏览器导出与 CSV 对拍复核（A/C）。

## 镜头 4 · 告警确认与关联原事件（约 45 秒）

- 画面/操作：`/alerts` 状态/级别筛选 → 查看/处置 → 状态迁移记录 → 管理员"确认告警"。
- 应出现结果：列表显示来源 ID 与关联原异常 ID；迁移记录追加（待处理→已确认→已恢复）；已恢复再确认报 409。
- 来源：`frontend/src/features/alerts/AlertsPage.tsx`、`api.ts`。
- 目前能否录：待现场验证（需真实异常事件 + 管理员账号）。
- 缺口：同版浏览器 + 真实异常触发（A/B）。

## 镜头 5 · 控制 ACK 后数据变化（约 50 秒）

- 画面/操作：设备详情"远程制冷控制" → 准备下发 → 确认开启制冷 → "最近 5 条命令"查询回执 → 遥测页看后续温度。
- 应出现结果：命令"设备回执：执行成功"；页面区分"MQTT 接受（不是执行确认）"与"有效回执接收"；后续采样温度变化。
- 来源：`DeviceControlPanel.tsx`；G1 `runtime-composition.json`（execution_count=1、10.002809→9.980946°C 软件仿真）；既有片段 `A-CONTROL-ACTUAL-COMPONENT.webm`。
- 目前能否录：部分能（有控制录屏片段；整条链路浏览器待现场）。
- 缺口：说明"软件仿真，不是实物制冷，也不等于降到恢复阈值"；不写成"控制导致恢复"因果（A）。

- 来源：`docs/modules/A/62-linked-correction-runtime.md`；G1 `actual_recovery_http_and_resolved_readback=true`。

- 缺口：无人值守恢复发送未完成（A+B）。
