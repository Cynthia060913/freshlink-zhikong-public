# 七测区、十四逻辑设备的连续仿真运行器

这不是十四台真实硬件，也不是完整A/B/C业务验收。复用已有SoftwarePlant与
DeviceRuntime，每测区一个温湿度采集身份、一个制冷执行身份；七区共十四身份。
示例四区属于冷库1、三区属于冷库2。各区热过程独立，属于工程仿真，不宣称实际
冷库热传导或实测苹果品质。三批同品种苹果、规则和绑定仍由B真实业务服务建立。

## 配置与运行

`fleet.example.json` 是无秘密占位配置，必须把十四身份注册到实际应用、绑定相应
真实B冷库，并由持有人为十四个独立MQTT账户配置最小ACL。采集者只能发布自己的
telemetry/heartbeat；执行者只读自己的commands、写自己的acks/heartbeat。
不得以同一个管理员账号供十四身份使用，也不把设备自报UUID当鉴权结果。

默认TLS8883，保留证书/主机名验证；自建CA按RuntimeSettings的ca_file配置。
明文只允许显式隔离的localhost/broker测试，不允许为图省事关闭证书检查。
每个设备密码由本人运行环境注入：键为
`FRESHLINK_SIM_<设备UUID去掉连字符并大写>_PASSWORD`；不写进JSON、命令行或日志。
`password_environment_name(UUID)`可获得准确键名。源码不包含真实账户密码。

在已核对的应用镜像/专用隔离Python环境中、backend目录运行：

```text
python -m app.modules.iot.simulator_fleet --config ../simulator/fleet.example.json --max-seconds 60
```

镜像只包含backend时，将非秘密配置单独只读挂载并使用其实际容器路径，不假定
`../simulator`已在最终镜像里。该命令不启动后端、Broker、A/C/B持续worker，不建共享
库表，不发送SMTP/飞书。不要使用宿主D盘Python安装依赖来运行。
不传max-seconds可持续运行；显式时限必须大于0且不超过3600秒。Ctrl+C按统一监督器
停止全部区；一组故障会停止兄弟区，不静默留下部分运行而显示全场景健康。

## 状态保护

七个.db路径必须在同一个专用状态目录、互不重复，设备UUID和账户名全局唯一。
检查全部凭据及所有已存在文件后才创建任何仿真状态。未知SQLite、其他表、身份不符、
符号链接或非普通文件均拒绝；先用只读连接核对，不把课程/应用数据库拿来自动升级。
失败留下本轮已创建的仿真状态供追溯，不删除旧状态。恢复时沿用每区原文件和身份，
停机缺口按已有规则显式保留，不补造缺失采样或伪装重启后制冷仍开着。

## 可重复的受控证明

`scripts/windows/check-simulator-fleet.ps1 -AppImage <已缓存应用镜像>` 新建随机专属
Docker内部网络和Broker，无宿主端口/真实配置/应用数据库/外部通知，不自动拉镜像。
十四个合成独立账号、各自主题ACL；所有仿真SQLite和报告在本轮私有work目录。
实际检查十四心跳、七路遥测、七执行器各一次控制、同命令原ACK重放/零额外执行、
七区后续降温以及传感器跨设备发布遭拒。结束只清本轮容器/网络，保留私有证据。

该证明没有A注册/持续服务、B三批规则、C持久化/CSV或两通知，不能记作完整十四设备
应用场景、第二机或E1。最终仍须按同一发布版本在共同应用与第二电脑复现。
